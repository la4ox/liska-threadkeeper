# ChatGPT follow-up plan

This is the short continuation plan for the ChatGPT exporter. Confirmed state and
evidence receipts remain in [`STATUS.md`](../STATUS.md); architecture and privacy
boundaries remain in [ADR-031](adr/031-loss-aware-archive-pipeline.md) and
[ADR-032](adr/032-staged-large-chatgpt-capture.md).

## Working baseline

The minimum useful ChatGPT path is live-verified:

- no-scroll exact graph capture with raw, manifest, canonical JSON, and Markdown;
- provider-current, explicitly selected, and all-leaf branch presentations;
- Downloads and Obsidian with destination-specific, hash-verified results;
- Canvas and loss-aware canonical blocks;
- current DOCX/PDF interpreter attachments;
- bounded sequential PNG acquisition, including historical assets;
- custom-GPT/project graph capture with an explicit archive-only attachment
  policy, durable warning, and zero binary authority;
- preview-shaped records retained with provenance and ordinary eligibility
  unless a future structural relationship proves a narrower asset family.

Every new slice must preserve raw bytes, append-only capture history, explicit
terminal states, and the existing no-credential-export boundary.

## Priority queue

### 1. Ordinary image families

- Add evidence-gated active support for `image/jpeg`, then GIF/WebP where live
  raw shapes and helper behavior actually match supported routes.
- JPEG is live-verified and enabled for the ordinary route. Explicit Library-ID
  evidence fails closed before active and passive winner selection, and
  PNG/JPEG bytes receive bounded structural validation before hashing.
- Archive reconnaissance found no ordinary GIF and only one WebP, which carries
  explicit Library-ID metadata and no captured binary. It is not ordinary-route
  evidence; GIF/WebP active widening remains deferred.
- A later official-export shard adds four `image/webp` metadata records without
  explicit Library markers and still zero GIF. Two corresponding ordinary URLs
  are currently unavailable; the two accessible conversations resolve to
  project routes. Treat them as project-owner evidence, not ordinary active
  authority. The next live gate is one WebP-bearing project capture proving
  raw-pointer/owner classification and an honest `not-attempted` result before
  any WebP resolver or byte validator is designed.
- Keep derived previews and ordinary images distinct before resolver dispatch.
- Preserve original bytes; do not introduce compression as an archival default.
- Live gate: fresh and historical examples, exact PNG/JPEG signatures,
  length/SHA-256/path reconciliation, byte-identical Downloads/Obsidian copies,
  and no leftover temporary tabs.

### 2. Special ChatGPT attachment families

- Classify and implement Library-ID assets separately.
- Offline classification is implemented without transport authority: exact raw
  source refs produce only opaque associated/ambiguous asset IDs, while
  malformed, conflicting or stale evidence fails closed.
- One exact Library-associated JPEG is live-verified through a separate planner
  and the existing page-owned file-ID transport. It consumes one of four active
  image slots; only the exact direct attachment ID can authorize the request.
- Pointer-only aliases may lose to that exact direct record, but malformed,
  nonempty direct, Library-bearing and interpreter-owned siblings remain hard
  blocks before eligibility.
- Library/gizmo/project/template identifiers are raw-only in canonical output;
  custom-GPT/template context retains only bounded boolean association facts.
- Custom-GPT/project route preservation and raw ownership classification are
  implemented. Live custom-GPT and project captures preserve complete raw and
  canonical evidence; a project sample retained nine attachment references as
  `not-attempted`, emitted one durable policy warning, and performed no binary
  work. Owner slugs/paths remain runtime-only.
- Do not guess `gizmo_id`, project IDs, or borrow the ordinary-chat route.
  Owner-context binary acquisition remains a future evidence-gated contract.
- Keep file-ID, interpreter/sandbox, Library, and future provider families
  discriminated in plan, audit, and terminal state.
- Live gate each family independently before enabling it generally.
- Implemented and live-verified: at most one exact Library `text/plain` attachment,
  with the same direct-ID/whole-ledger/owner checks and immediate committed-raw
  replan. Library CSV -> JPEG -> text/plain -> ordinary images preserves the
  existing CSV/JPEG priority and shares the same four slots, 20 attempts and
  128 MiB budget. The additive optional audit count keeps old shapes valid and
  never labels text as an ordinary image.

### 3. Deep Research binaries and collisions

- Reconcile research-produced files, images, citations, and tool events without
  flattening canonical evidence.
- Preserve content-addressed binary names and explicit provenance when several
  research outputs use similar titles.
- Verify that legacy Markdown omissions are completely explained by canonical
  blocks and asset states.
- The current-branch destination-receipt slice is implemented and live-verified
  on a standard research-heavy chat. One produced DOCX reached Downloads and
  Obsidian under the same SHA-256 path; each note carries its destination's
  exact final manifest hash and one verified local archive link.
- Archive-bound Markdown now uses capture-scoped filenames and never overwrites
  an occupied path. Synthetic regressions cover identical display intent with
  distinct content paths, destination divergence, repeated capture writes, and
  equal bytes retained under distinct allowed MIME-derived targets.
- Ordinary append lookup also excludes every same-conversation note carrying a
  top-level archive-capture, manifest-hash, or presentation-mode marker. A later
  mutable export therefore cannot append to or overwrite an immutable snapshot.
- All-branches leaf notes and their index now consume strict destination-owned
  archive receipts. They preserve their prepared filenames, carry the exact
  final manifest hash, and expose only that destination's confirmed
  capture-level local attachment links. Missing or hostile receipt input blocks
  only the affected destination before presentation dispatch.
- A live File canary reconciled raw, manifest and canonical provenance; both its
  leaf and index contain the same exact manifest SHA-256 and the same resolving
  content-addressed DOCX link. The index points to the exact emitted leaf name,
  with no doubled capture suffix.
- A later two-destination canary repeated the same provenance checks in both
  Downloads and Obsidian. Their archive/DOCX bytes and hashes match; File and
  Obsidian leaf sizes differ only through the expected destination-specific
  long-message transform, and each exact serialization is budgeted separately.
- Canonical research evidence remains typed rather than flattened. The live
  sample retained citations, reasoning, code, execution output, tool roles and
  attachment blocks; projection regressions account explicitly for citation
  and Canvas omissions.
- Current and selected single-branch notes now replace only an exact
  destination-owned, fetched `sandbox:` occurrence. Every mismatch retains the
  provider link and verified appendix; raw/canonical evidence is unchanged.
- A fresh live legacy chat confirmed three same-title groups in one complete
  archive: two PDF records, five DOCX records, and three further DOCX records.
  All ten retain distinct opaque asset identities and canonical entries. Its
  raw owner context is unsupported or ambiguous, so acquisition correctly made
  no resolver calls and left every record `not-attempted` without SHA-256 or a
  local path. This closes the live identity/preservation collision gate, but not
  destination naming for multiple fetched same-title binaries and does not
  authorize a broader resolver route.

### 4. Real wide-branch stress

- Run selected-branch and all-branches export on a genuinely wide private graph.
- Measure picker responsiveness, sequential write volume, index correctness, and
  cancellation behavior.
- Add picker virtualization only if live evidence shows it is necessary.
- Aggregate all-branches work/write ceilings are implemented before any
  unusually wide graph can export automatically; keep those fixed limits unless
  a separate evidence-backed maintainer decision changes them.
- Implemented: one prepared validation/catalog session, O(1) ordinal lookup,
  parent-only path reconstruction, exact two-pass File/Obsidian byte accounting,
  terminal exact-name File receipts, per-destination failure isolation, and a
  trusted cooperative Stop control. Structural rejection precedes every write;
  byte rejection retains confirmed archive evidence but writes no branch view.
- Synthetic evidence now covers 12,000 depth, 400 shared-prefix leaves, 80-leaf
  task-yield cancellation, exact cap boundaries, settings drift, midnight
  filename stability, destination-specific transforms, unknown Downloads
  ownership, and index suppression.
- Live evidence: a one-leaf File bundle passed with exact branch/index filenames,
  a resolved index link, and hash-bound raw/manifest/canonical companions. The
  239-leaf private graph reached a usable picker in about 65 seconds; picker
  cancellation wrote nothing.
- The same live graph correctly refused `Export all branches` before any output
  at the 1 GiB expanded-source-work ceiling. Its existing matching canonical
  snapshot measures 2,285 nodes, 239 leaves, 68 branch points, 230,694 path
  visits, and 1,128,535,662 expanded source bytes (1.051 GiB). Do not raise the
  ceiling silently. Maintainer decision: keep the refusal, or review a 1.25 GiB
  bound and then run the complete File/Obsidian write/index reconciliation.
- Exact Markdown accounting now includes destination-finalized provenance and
  attachment-link decoration, guarded by filename/length/SHA parity between dry
  and write passes.
- Exact retained-byte accounting is implemented for each successfully finalized
  destination: its final raw/manifest/canonical trio plus every confirmed binary
  once, never once per branch. Initial representable seeds above 2 GiB reject
  before Markdown measurement. The later operation-local ledger now charges
  confirmed and unknown raw/binary attempts exactly once across all-branches
  writes; not-dispatched attempts charge zero. It is bounded attempt evidence,
  not a whole-operation pre-write or net-disk claim.

### 5. Real staged capture above 16 MiB

- Verify a real provider raw response above the inline threshold through staged
  OPFS transport, not only synthetic fixtures.
- Reconcile raw/manifest/canonical hashes, UTF-8 chunk boundaries, cleanup,
  File/Obsidian release, and worker restart behavior.
- Keep the existing 64 MiB raw boundary until evidence justifies changing it.
- The modern opaque-replay route previously rejected above 16 MiB before
  downstream staging. A versioned staged-v2 core is now implemented but remains
  internal/test-selectable: v1 inline is still the only production default.
  MAIN exposes credential-free chunk metadata/readers; background owns random
  stage allocation, pinned-document transfer, seal and exact late-settlement
  cleanup. A separate PR must adapt content results, own late runtime responses
  and activate v2 without changing sub-16 MiB behavior.
- Local archive measurement found no natural retained raw above 16 MiB; the
  largest current positive is 13,117,554 bytes. Canonical derivatives above
  16 MiB are not raw-ingress evidence and must not close this gate.

### 6. Additional binary types

- Exercise currently available XLSX, PPTX, ZIP, text, audio, and video examples.
- Add a provider route only after identifying its exact live contract.
- Keep unsupported or unavailable files as honest retained references rather
  than silently dropping them.
- Generic ZIP is now live-confirmed through the existing page-owned/interpreter
  evidence route. Two content-addressed files (6,545 and 7,055 bytes) opened as
  readable seven-entry archives, matched canonical length/SHA/path evidence, and
  contained no Office package markers. Acquisition now requires exact
  `application/zip` plus a bounded ordinary-local-header or empty-EOCD prefix
  and minimum fixed-record length before hashing. This is not full archive
  integrity validation; split/SFX ZIP remains unsupported without evidence.
- The same live capture kept five PPTX and two text/plain references
  `not-attempted`. ZIP success does not authorize relabeling those records or
  claim Office-package support.
- A separate fresh standard-owner capture retained two `text/csv` references as
  distinct `not-attempted` assets while the active route fetched four JPEGs.
  Follow-up raw-first analysis proved that both CSV records are unambiguous
  Library attachments with exact direct file-ID evidence, no interpreter
  ownership, and every existing Library admission invariant satisfied except
  the former JPEG-only MIME gate.
- A narrow candidate now attempts at most one exact Library CSV before Library
  JPEG/ordinary images. It consumes one of the existing four active slots,
  shares unchanged request/byte budgets, replans from committed raw immediately
  before dispatch, never falls through to passive retry, and persists exact
  bytes only as a content-addressed download. The second CSV remains honestly
  `not-attempted`.
- The exact installed canary closed that gate. It fetched 14,717 CSV bytes whose
  raw size fact, content-addressed filename, manifest and canonical length/hash
  all agree; the second 751-byte CSV remained `not-attempted`. The four active
  slots held one Library CSV, one Library JPEG and two ordinary JPEGs. File and
  Obsidian share seven byte-identical archive artifacts and identical Markdown;
  File alone adds its expected canonical HTML/receipt. Library IDs remained
  raw-only and no signed URL entered durable output. This proves one passive
  Library CSV contract, not Library text/plain or arbitrary CSV syntax.
- The installed trusted-click text/plain canary closed this narrow gate. The
  deterministic 4,233-byte candidate became the same content-addressed `.txt`
  in File and Obsidian; physical bytes, path/length/hash, manifest and canonical
  agree. The second eligible record remains `not-attempted`; the aggregate
  audit records one text/plain attempt inside four total active operations.
  The selected Library ID has zero non-raw matches; no URL-valued field was
  tied to that record. Its ordinary direct attachment ID remains under the
  established source-provenance contract, independent of acquisition, and a
  focused regression excludes it from resolver warnings/receipts. Exact MIME agreement
  still permits only opaque byte retention: no decoding, newline rewriting,
  encoding guarantee or inline preview. General Library text remains unsupported.

### 7. User-facing derived outputs

- The pure `liska-html/1` renderer and opt-in current/selected File delivery are
  implemented. HTML is derived only from a hash-verified canonical archive and
  carries a deterministic provenance receipt; it is never reconstructed from
  legacy Markdown.
- Destination-finalized asset binding is implemented for current/selected File
  snapshots. A real archived JPEG passed exact byte/path/hash reconciliation,
  rendered through a local content-addressed image reference, and retained an
  honest placeholder for its unbound sibling.
- The all-branches HTML stack is implemented and live-verified. One prepared
  ordinal-derived session validates the graph and destination-finalized asset
  bindings once, dry-measures every leaf/index pair, accounts aggregate work and
  physical writes, then recreates and sends one pair at a time. Cancellation,
  unknown-write stop, independent Markdown/HTML completion and deterministic
  local index behavior are wired through the exporter bootstrap.
- Canonical authorization and background persistence are active only for an
  opted-in File all-branches request. Plain captures create presentation
  evidence only after the exact File archive trio is confirmed; attachment
  captures accept only matching destination-finalized evidence. HTML and each
  locally built receipt retain independent confirmed/unknown/not-dispatched
  outcomes, one-send transport and no retry/completeness invention.
- The exact installed live canary retained raw/manifest/canonical, two PNGs,
  two Markdown leaves plus index, two HTML leaves plus index and three receipt
  files. Every HTML byte length and SHA-256 matched its receipt, relative
  navigation rendered in Comet, and no provider or transient download route
  remained in the HTML.
- Automatic PDF remains a separate transport/rendering decision after HTML
  bundle behavior is stable.
- Tail-only image-aware Obsidian append is implemented and installed-live-
  verified under ADR-045. A synthetic production-message canary closed new-tail
  creation, different-ID/same-byte reuse, exact replay, filesystem readback and
  setting restoration. A separate scheduling-only instrumented canary proved
  the unchanged production base reread refuses an externally changed note after
  asset verification, while retaining the verified asset as honest reusable
  evidence. Exact production bytes were rebuilt and reinstalled afterward.
- Add an explicit snapshot deduplicator; never replace immutable captures by
  default.
- Pure analysis core implemented on `codex/snapshot-dedup-analysis`: explicit
  selected bytes only, strict bounded JSON, exact raw/manifest/assets/canonical
  replay, sparse preserve-only classifications, path-free reports and no
  mutation capability. ADR-043 records the contract. A filesystem/UI adapter,
  backlink coverage, preview, quarantine/undo and cleanup confirmation remain
  separate required slices.
- Local analysis/report page implemented on `codex/snapshot-analysis-ui`:
  repeated explicit folder picks, preflight-before-read, sequential cancellable
  reads/hashes, content-free ordinal rendering and one honest Save As JSON
  report. It has no cleanup controls or mutation capability. The installed
  Comet picker/analyze/Save As path is live-verified on two real snapshots: the
  physical report is byte-identical to its oracle, late terminal completion is
  reconciled without retry, and a cancelled later picker preserves the result.
  A separate 16-folder synthetic acceptance selected exactly 255 MiB, completed
  one uninstrumented Analyze, and accepted a native Cancel while the page showed
  its in-progress analysis status, with no late report or download. All 36
  source hashes remained unchanged. This closes near-limit read/copy/hash
  responsiveness in installed Comet; parser-heavy near-limit replay remains a
  separate live gate.
- Ordinary Google Chrome portability is live-verified on two synthetic raw-only
  folders: both exact 2-file / 1,081-byte cards rendered, Analyze reached the
  unchanged-source terminal state, both snapshots remained `Unverifiable`, no
  candidate relationship was invented, and Save was not invoked. Post-run
  hashes/sizes/timestamps matched; no new report or partial appeared. This does
  not claim every browser family or provider content-script route.
- After manual capture and recovery paths are boringly reliable, add a separate
  user-controlled daily backup service above the provider adapters. Begin with
  a rate-limited, resumable baseline inventory/export of every accessible chat;
  it may intentionally take several days. Thereafter, poll only bounded
  provider-specific chat-index/history metadata and export the provider IDs with
  a proven revision, update timestamp, cursor, or equivalent change marker.
  Never reopen every chat daily merely to discover whether it changed, and do
  not guess change from title, order, page presence, or local elapsed time when a
  provider has no reliable signal.
- Give each provider a separately reviewed discovery contract, cooldown,
  exponential backoff, daily request/page budget, resumable cursor and durable
  per-chat ledger. The ledger must expose baseline/export/check timestamps,
  observed change evidence, deferred/rate-limited/missed/error states, pause,
  manual retry and catch-up after downtime. Every successful update remains a
  new append-only raw/manifest/canonical snapshot; readable incremental output
  requires the same provider identity and a reverified historical prefix. The
  scheduler must not silently overwrite snapshots, invent completeness after a
  missed run, or acquire account-wide/provider network authority except through
  that explicit opt-in discovery contract.
- Preserve four independent layers instead of collapsing them into one mutable
  system: (1) periodic official exports as cold external evidence, roughly every
  one or two months; (2) daily update-driven Liska append-only raw/manifest/
  canonical snapshots; (3) the existing readable Markdown/HTML branch-aware
  presentation layer; and only then (4) a future living-memory layer for themes,
  links, unfinished threads and semantic recall. Later layers may index and
  reference earlier evidence but must never silently rewrite, deduplicate, or
  delete its archive truth. Design the living-memory system only after the first
  three layers have boring recovery and reconciliation paths.

### Cross-cutting hardening

- Repair current ChatGPT capture compatibility as a separate slice. Fresh live
  historical-image retries confirmed three honest pre-destination stops:
  A-strict can reject a newly observed opaque path, passive structured capture
  can time out after the page uses a different request family, and the DOM
  fallback currently finds no primary turn selectors on that UI. Do not weaken
  complete-graph claims or fold this provider drift into HTML asset binding.
  The timeout is specifically the 15-second no-claim timer for the legacy
  queryless singular request, not a payload/image timeout. First add value-free
  strict-replay mismatch categories, then inspect current live turn attributes;
  widen neither route equivalence nor DOM selectors without that evidence.
- Current candidate adds one replay-only fixed diagnostic:
  `target-not-observed-singular-path-seen`. It records only that the exact
  current singular pathname was seen before the existing no-claim deadline;
  it does not claim a GET, response, completeness, eligibility or usable bytes.
  Candidate/claim/dispatch rules, timers, exact plural query grammar and generic
  `target-not-observed` remain unchanged.
- One bounded fresh-tab DOM inspection read only aggregate shapes and found the
  current selectors intact: five `div[data-turn-key]` roots, each with one user
  bubble, one assistant marker and one assistant Markdown block, plus the exact
  timeline scroller. The earlier zero-turn symptom was not reproduced; do not
  widen selectors without a contrary current shape.
- The first exact-build A-strict canary exposed a separate orchestration hang:
  the UI stayed `Syncing…` for more than five minutes although replay's
  background deadline is 190 seconds. No marker tab, Save As dialog, fixed G2O
  error, Download/Obsidian artifact or mutable note appeared. The content-side
  runtime message had no deadline. A bounded 205-second envelope is now a
  candidate; only its self-created timeout maps to fixed detail
  `opaque-replay-runtime-message-timeout`. It never retries, cancels, writes or
  exposes the late/private runtime outcome.
- Before that envelope could be exercised, live extension diagnostics exposed
  service-worker registration status 15: a transitive browser decoder export
  eagerly evaluated `document.createElement` in the worker. The current
  candidate aliases only that exact dependency to its equivalent DOM-free
  table decoder and runs a fail-closed transitive emitted-worker guard after
  every production build. Old-dist rejection, full decoder parity, 30 focused
  guard tests, the 7,321-test complete suite and independent review are clean;
  the exact installed build then registered its worker and completed one fresh
  foreground historical-chat replay in about 30 seconds. File and Obsidian
  received identical complete structured Markdown; the immutable archive's raw
  response and four fetched JPEG/PNG assets reconcile to manifest lengths and
  SHA-256 values, while two unsupported references remain honestly
  `not-attempted`. The worker/message/replay live gate is closed.
- Shared graph membership validation is now linear, ChatGPT sandbox-link parsing
  is bounded, and DeepSeek normalization has an explicit post-raw node ceiling.
- Settings-stable durable routing is implemented across first-party archive,
  binary, and Markdown writes. Every new write carries a detached, secret-free
  settings snapshot; background rejects drift or a newly disabled destination
  as `settings-changed` before dispatch. This is an admission-time guarantee,
  not atomic cancellation or fixed physical-vault identity.
- Staged settings mismatch can exact-abort only the named temporary stage after
  ordinary sender validation. Cleanup failures retain only the fixed
  archive/binary cleanup-deferred warning; arbitrary private errors do not cross
  the boundary.
- Operation-local all-branches write accounting is implemented for raw,
  manifest, canonical, and binary attempts. Confirmed and unknown bytes from
  every requested destination seed the physical budget; not-dispatched attempts
  charge zero. Receipts are not added twice and remain the sole authority for
  Markdown/index eligibility, provenance, links, fetched assets, and
  localization.
- Sink outcomes are exact opt-in evidence. Legacy durable callers and ordinary
  Markdown retain their old response shapes. Cleanup failure cannot erase a
  confirmed write, while malformed/incomplete/foreign ledger evidence blocks
  further Markdown instead of selecting receipt-only fallback.
- The automatic ledger consumer remains all-branches only. Current/selected and
  DeepSeek expose the optional seam but do not manufacture unused audit state;
  no persistence across browser/worker restart, retry, deletion, recovery, or
  net-disk claim is implied.
- Typed DOM history loading is now separate from archive completeness. Known
  partial Base/Gemini results cannot replace a longer exact same-conversation
  mutable Obsidian note, and an untrusted old count fails closed before image or
  Markdown writes. New partial notes, File/Clipboard, valid complete/unknown traffic,
  and immutable snapshots retain their earlier behavior. This is a count-based
  shrink guard, not proof of prefix alignment.
- Keep the completed aggregate branch/write ceilings fixed. The remaining live
  choice is whether to retain the honest 1 GiB source-work refusal or explicitly
  review a 1.25 GiB bound before a complete wide-graph File/Obsidian run.
- Re-run focused security/diff review at meaningful boundaries, not after every
  cosmetic change.
- Continue repository-wide triage and the untouched-provider upstream audit in
  the [security follow-up plan](security-todo.md).

### 8. Official export import and cross-format reconciliation

- Pure core implemented: stream a bounded official conversations array, select
  one exact provider ID, and retain only that object's original bytes with
  index/offset/source-length provenance. No neighboring conversation content is
  copied into the result.
- Official captures use an explicit file-slice source instead of a fabricated
  HTTP endpoint. Existing web and DeepSeek manifest bytes remain unchanged.
- Official parent-only graphs derive child links in parsed mapping order and
  disclose that derivation. Mixed explicit/derived links fail closed; metadata
  lineage never overrides node `parent`.
- Asset descriptors are preserved as metadata-only `not-attempted` records.
  This core does not search the export directory or infer binary ownership.
- Canonical refusal returns `raw-only` with the verified excerpt and manifest;
  it never upgrades a failed graph to a complete archive.
- Local evidence covers the real 109,346,038-byte export and one real branched
  conversation without logging content. See ADR-037 and STATUS.
- Pure compare-only core implemented: `liska-chatgpt-comparison/1` accepts one
  web and one official canonical snapshot of the same exact conversation,
  scopes every fact left/right, and reports exact-ID matched, source-only, and
  typed conflicting facts without copying conversation prose or merging inputs.
- A private content-free real pair exposed 200 web-only nodes/messages while all
  42 exact asset IDs matched. This is retention evidence, not proof of why the
  official export omitted those nodes or that either source is complete. See
  ADR-038 and STATUS.
- Do not merge canonical archives yet. Source refs currently name artifact IDs
  without capture IDs, so concatenating provenance across snapshots would be
  ambiguous. Do not infer equality from title, timestamp, filename, archive ID,
  or current-branch Markdown.
- Local File flow implemented: the popup opens a dedicated extension page with
  two read-only JSON inputs; the exact web conversation ID selects one official
  conversation, and one deterministic Save As ZIP preserves official raw,
  manifest, canonical, comparison, and a root bundle manifest. Canonical refusal
  produces an explicit raw-only recovery ZIP rather than false success.
- The selected web bytes are bound by exact length/SHA-256; source filenames and
  paths never enter bundle metadata. Because file selection grants no write
  authority, the user chooses physical same-folder placement in Save As.
- Stacked Obsidian candidate implemented: direct extension-page delivery is
  explicit and off by default; it requires Local REST API 5.5+ atomic
  `If-None-Match: *`, preflights every fixed target, writes/readbacks each
  artifact sequentially, and commits the unchanged root manifest last. Any
  uncertainty stops successors without retry or deletion. Installed 5.1.0 was
  correctly refused before vault-path access; after updating to 5.5.2, a real
  normalized five-artifact writer/readback, root-last completion, deliberate
  412/no-overwrite race and post-admission cancellation all passed. Native
  `chrome-extension://` file-picker/result rendering and actual page unload are
  not claimed by that direct production-core canary.
- Stacked multi-shard candidate implemented: legacy `conversations.json` remains
  supported, while explicitly selected `conversations-NNN.json` files are sorted
  and fully validated sequentially under shared 2 GiB / 100,000-record / 1,000-
  source ceilings. Exact IDs are unique across the whole set; later shards cannot
  be skipped after a match. Shard-local provenance retains only numeric index.
- Four measured manifest-v1 exports consistently declare six shards `000…005`.
  A real 477,261,486-byte six-shard smoke completed normalized in about 11.7 s.
  Four literal `{}` padding records in shard 004 are counted, disclosed and
  ignored only for identity validation; nonempty identity-free records still
  fail closed. An exact installed-page run accepted six files and verified an
  Obsidian-only snapshot; direct exact-head canaries separately close shuffled
  ordering, later-shard cancellation with zero output, ZIP parity and omitted-
  target refusal. Installed negative-input acceptance now also closes invalid-
  extra-file refusal and a trusted native Cancel against a transient held read
  of a synthetic 512 MiB later shard. The clean receipt marked the native click
  trusted (`isTrusted: true`) and recorded the exact no-output warning, hidden
  results, restored controls, zero baseline/terminal Local REST requests,
  unchanged sources and no new ZIP. Arbitrary uninstrumented timing and actual
  page unload remain unclaimed.
- Optional manifest-guided admission candidate implemented: a separately
  selected exact `export_manifest.json` is capped at 2 MiB, strictly parses only
  provider schema v1, projects the logical `conversations.json` declaration and
  requires exact equality with separately selected canonical shard basenames
  before either source scan. Missing, duplicate, unexpected, path-like, stale,
  cancelled or malformed selections fail with zero later work. Raw manifest
  bytes and unrelated inventory never enter the UI result or durable output;
  the explicit clear control returns to no-manifest/legacy mode without reload.
  This validates declared names only, not shard content authenticity or export
  completeness. Installed acceptance now also passes: one measured provider
  manifest plus six synthetic shards reached Save As and deliberate no-save;
  omitting one declared shard refused before Save As; Clear manifest preserved
  all other selections. Post-run hashes/sizes matched and no output appeared.
- Automatic manifest/directory/export-ZIP discovery, external binary import,
  archive merge, and snapshot deduplication remain later explicit slices.

### 9. Adjacent provider: Dots chat export

- Treat Dots as a separate provider investigation, not as another ChatGPT URL or
  a DOM-selector variant.
- Confirmed false positive: two trusted clicks on `https://chatgpt.com/dots/home`
  produced separate 9,091-byte files that were identical after removing only
  generated ID/timestamps. They were labelled `source: chatgpt`, used a
  timestamp-derived identity, and contained only ten visible DOM messages (five
